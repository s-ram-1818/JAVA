# CSRF (Cross-Site Request Forgery) - Complete Notes

---

# What is CSRF?

CSRF (Cross-Site Request Forgery) is a web security attack where a malicious website tricks an authenticated (logged-in) user into performing unwanted actions on another website.

The attack succeeds because browsers automatically send cookies with requests.

---

# Definition

CSRF is an attack that forces a logged-in user to execute unwanted actions on a web application where they are authenticated.

---

# Why Does CSRF Occur?

Browsers automatically send:

- Session Cookies
- JSESSIONID
- Authentication Cookies

with every request to the associated website.

An attacker exploits this behavior to perform actions on behalf of the victim.

---

# Real World Example

Suppose a user logs into:

```text
https://bank.com
```

Bank creates a session:

```http
Set-Cookie: JSESSIONID=abc123
```

Browser stores the cookie.

---

## Legitimate Request

```http
POST /transfer

amount=1000
to=Ram
```

Browser automatically sends:

```http
Cookie: JSESSIONID=abc123
```

Bank verifies session and processes the request.

---

# CSRF Attack Example

User is still logged into bank.com.

User visits:

```text
https://evil.com
```

Attacker's page contains:

```html
<form action="https://bank.com/transfer" method="POST">
    <input type="hidden" name="amount" value="10000">
    <input type="hidden" name="to" value="Attacker">
</form>

<script>
document.forms[0].submit();
</script>
```

Browser automatically sends:

```http
POST /transfer
Cookie: JSESSIONID=abc123
```

Bank thinks the request came from the user and transfers money.

---

# CSRF Attack Flow

```text
User Login
    |
    v
Session Cookie Created
    |
    v
Browser Stores Cookie
    |
    v
User Visits Malicious Site
    |
    v
Malicious Site Sends Request
    |
    v
Browser Automatically Attaches Cookie
    |
    v
Server Accepts Request
    |
    v
Action Performed
```

# Requests Vulnerable to CSRF

Usually state-changing requests:

```http
POST
PUT
PATCH
DELETE
```

Examples:

```http
POST /transferMoney
POST /changePassword
PUT /updateProfile
DELETE /deleteAccount
```

---

# Requests Usually Safe

```http
GET
```

Examples:

```http
GET /users
GET /products
GET /orders
```

GET should only fetch data.

---

# How CSRF Protection Works

A server generates a unique CSRF token.

The token must accompany every state-changing request.

---

# What is a CSRF Token?

A CSRF token is:

- Random
- Unique
- Secret
- Generated by the Server

Example:

```text
abc123xyz987
```

---

# CSRF Protection Flow

```text
User Opens Form
      |
      v
Server Generates Token
      |
      v
Token Added To Form
      |
      v
User Submits Form
      |
      v
Token Sent Back
      |
      v
Server Validates Token
```

---

# Form Without CSRF Protection

```html
<form action="/transfer" method="POST">
    <input name="amount">
    <button>Transfer</button>
</form>
```

---

# Form With CSRF Protection

```html
<form action="/transfer" method="POST">

    <input
        type="hidden"
        name="_csrf"
        value="abc123xyz">

    <input name="amount">

    <button>Transfer</button>

</form>
```

---

# Request Sent

```http
POST /transfer

amount=1000
_csrf=abc123xyz
```

---

# Validation

Server checks:

```text
Submitted Token == Stored Token ?
```

If valid:

```text
Request Accepted
```

If invalid:

```http
403 Forbidden
```

# Getting CSRF Token in Spring Boot

## Method 1: Direct Injection

```java
@GetMapping("/csrf-token")
public CsrfToken csrfToken(CsrfToken token) {
    return token;
}
```

Response:

```json
{
  "headerName":"X-CSRF-TOKEN",
  "parameterName":"_csrf",
  "token":"abc123xyz"
}
```

---

## Method 2: Using HttpServletRequest

```java
@GetMapping("/csrf-token")
public String csrfToken(HttpServletRequest request) {

    CsrfToken token =
        (CsrfToken) request.getAttribute("_csrf");

    return token.getToken();
}
```

---

# Complete CSRF Endpoint Example

```java
@RestController
public class CsrfController {

    }

}
```

# Cookie-Based CSRF Token Repository

Spring can store token in a cookie.

Configuration:

```java
@Bean
SecurityFilterChain securityFilterChain(HttpSecurity http)
        throws Exception {

    http.csrf(csrf ->
        csrf.csrfTokenRepository(
            CookieCsrfTokenRepository
                .withHttpOnlyFalse()
        )
    );

    return http.build();
}
```

# Common Causes of 403 Forbidden

## Missing Token

```http
POST /users
```

Result:

```http
403 Forbidden
```

---

## Invalid Token

```http
X-CSRF-TOKEN: wrongToken
```

Result:

```http
403 Forbidden
```

---

## Session Expired

Session destroyed.

Stored token no longer exists.

Result:

```http
403 Forbidden
```

# CSRF and Session Authentication

Session login:

```text
Login
   |
JSESSIONID
   |
Browser Sends Automatically
   |
CSRF Possible
```

Therefore:

```text
CSRF Protection Required
```

---

# CSRF and JWT Authentication

JWT login:

```http
Authorization: Bearer eyJ...
```

JWT is manually added by frontend.

Browser does not automatically send it.

Therefore:

```text
CSRF Usually Not Required
```

Common configuration:

```java
http.csrf(csrf -> csrf.disable());
```

---

# Disable CSRF

```java
@Bean
SecurityFilterChain securityFilterChain(HttpSecurity http)
        throws Exception {

    http.csrf(csrf -> csrf.disable());

    return http.build();
}
```

---

# When Should CSRF Be Enabled?

Enable CSRF when using:

- Session Authentication
- Form Login
- Cookie-Based Authentication
- JSESSIONID

Example:

```java
http.formLogin(Customizer.withDefaults());
```

---

# When Is It Usually Disabled?

Disable CSRF when using:

- JWT Authentication
- Stateless REST APIs
- Mobile Applications
- React + JWT
- Angular + JWT

Example:

```java
http
    .csrf(csrf -> csrf.disable());
```
